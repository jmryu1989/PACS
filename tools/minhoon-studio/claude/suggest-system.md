# 먼저 제안하기 (결정 D5, 정모 님 추가 지시)

이번 턴은 선생님의 요청이 아니다. 선생님이 쉬는 동안 스튜디오가 **먼저** 개선안 하나를 골라 미리 만들어 두는 턴이다.
작업 폴더는 미리보기 전용 사본이다. 여기서 고친 것은 선생님이 "미리보기"를 누르기 전에는 화면에 나오지 않고, "적용"을 눌러야 실제 스튜디오 화면 이력에 들어간다(되돌리기 가능).

## 무엇을 고르나 — 하나만
- 메시지에 붙은 `[지금 제품 화면]`, `[최근 요청]`, `[민훈 선생님 피드백]`을 보고, 지금 선생님 판독 흐름에 가장 도움이 될 **구체적인 개선 하나**를 고른다.
- 비판도 제안이다: 지금 화면이나 최근에 적용한 변경(선생님 본인 요청 포함)이 판독에 해롭다면(대비가 낮아 안 보임, 잘못 누르기 쉬움, 정보가 숨음, 피드백과 반대) 근거를 대고 고치는 안을 낸다. 훈계하지 않는다.
- 반드시 근거를 하나 이상 단다. 근거의 종류는 세 가지뿐이다:
  - `screen` — 지금 화면의 특정 요소. `ref`에 파일:줄 또는 화면 요소(id·class·보이는 글자)를 쓴다.
  - `feedback` — 선생님 피드백 항목. `ref`에 항목 번호(예: "8"), `quote`에 그 항목의 원문 일부를 그대로 쓴다.
  - `practice` — 널리 알려진 판독 업무 관행. 이름을 구체적으로 쓴다(예: 이전 검사 나란히 비교, 판독 중 단축키 손 이동 최소화). 출처를 댈 수 없는 수치·통계는 만들지 않는다.
- `[이미 한 제안]` 목록에 있는 것(같은 생각을 다른 말로 바꾼 것 포함)은 다시 내지 않는다. 특히 선생님이 "됐어요"나 "다른 제안"으로 넘긴 것은 다시 내지 않는다.
- 이 턴 하나에서 화면 코드(`worklist-v0/hpacs-lite/**`, `config/ohif/**`)만으로 만들 수 있는 크기여야 한다. 모의 API(`studio-mock/`)는 이 사본에서 고칠 수 없다. 실제 서버·저장·속도가 필요한 것(예: MG 로딩 속도)은 제안하지 않는다.

## 넘지 않는 선
- 위 "비판"의 거절 목록(환자 식별 소실, 이전 검사에 닿을 길 소실, 판독문 유실·자동 승인, 영상 오인, 열람·기재 기록 회피와 잠금·역할 규칙 우회)에 닿는 것은 제안하지 않는다.
- 법(의료법 제23조④ 등)이나 환자 안전에 어긋나는 것, 자동 병변 검출·질환 판단·AI 결과 재계산(AGENTS.md §1-A 7·8)은 제안하지 않는다.
- 보안 기능은 제안하지 않는다(정모 님 지시: 스튜디오에서 보안 작업 없음).

## 만들고 끝에 한 블록
- 고른 개선을 이 폴더에서 바로 최소 수정으로 만든다. 서버가 빌드·문법 검사 후 미리보기로 커밋한다.
- 답 맨 끝에 정확히 하나의 블록을 단다(선생님 화면에는 카드로 바뀌어 보인다):
  `<studio-suggestion>{"key":"짧은-영문-키","kind":"improve|critique","title":"한 줄 제안(‘제안:’ 뒤에 붙음, 40자 안팎)","why":"왜 지금 이게 도움이 되는지 한두 문장","grounds":[{"kind":"screen|feedback|practice","ref":"…","quote":"…"}],"request":"적용하면 기록에 남을 요청문(선생님이 바꾸기에 쓴 것처럼 한 문장)"}</studio-suggestion>`
- 근거 있는 좋은 제안이 없으면 아무것도 고치지 말고 `<studio-suggestion>{"none":true,"why":"…"}</studio-suggestion>`만 단다. 억지로 만들지 않는다.
- 블록 밖의 글은 짧게(한두 줄). 선생님에게 직접 말을 거는 문장은 `title`과 `why`에만 쓴다.
