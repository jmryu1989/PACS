# EMR-D workflow evidence

REQ R5-21/22/23 → risk of accepting another source, omitted work, or lost failure evidence → the `EMR-D workflow` and `EMR-D evidence` cases in `server_test.cjs`, plus `server_mutants.py` and the R1 selection in `mutants.py`.

The workflow has three jobs. `emr-d` (120 minutes) and `emr-d-server-mutants` (270 minutes) run independently; `emr-d-gate` (10 minutes) waits for both with a failure-safe condition, downloads both artifacts from the same workflow run and checks the same seven records. Every job checks out `TARGET_SHA`. Before artifact upload each producer runs `same_source.py --producer main|server-mutants` against its own records and final checkout, with failures enforced. This retains rejection of post-record producer drift that a fresh gate checkout alone could not observe. The final invocation has no producer selector and requires all seven records. No record is added or omitted. The budget critical path is `max(120, 270) + 10 = 280` minutes, formerly `270 + 120 = 390`; the previous measured 128–192 minute mutant job remains the dominant work, plus the added boundary mutants and the small gate. This is a budget, not a hosted timing measurement. PR CI/G3 and binding review remain commander's separate gates.

`same_source.py` reads the declarations from the fixed Git commit. It compares the complete declared and recorded trees with that commit, the recorder's before/after snapshots, and the final checkout (HEAD, membership and content). Raw recorded hashes must match the commit's original bytes or a whole-file LF/CRLF conversion; final content is compared after CRLF → LF normalization. Other changes are refused. The contract case list, allowed skip, 26 R1 mutant IDs and explicit exclusions are independent declarations in `emr/units/d.json`; duplicates and other selections fail.

The typecheck uses the installed TypeScript CLI with incremental compilation disabled, `--listFiles` and `--extendedDiagnostics`. The recorder argv must identify Node and the installed `typescript/bin/tsc` entry point (normalized relative or absolute paths); no shell-string containment or option parser is used. Its output must name every source and include actual check statistics. The workflow test runs that command on valid, syntax-error and type-error programs, with absent, present and changed caches; an observed cache read fails the control. The generated Prisma client and dependency inputs are tied to the existing schema and lockfile contract, not claimed as a reproducible build of third-party tools.

The live class compares the selected tag's immutable ID and revision with the verified identity before DB startup, uses that ID for subsequent commands, and prints `EMR_D_USED_IMAGE`. The final gate checks that result against the identity consumed by the live recorder. The pure test substitutes Docker inspection and the DB entry point; it starts no containers.

Shell steps execute in GNU Bash, including line continuation, quoting and function extraction. The recorder itself parses its options. The test's child substitution creates explicitly synthetic evidence-reader fixtures. Actual work is checked separately through TypeScript, Node reports, mutant results, the live result and image/identity execution. The Docker build-input contract is explicitly `package.json`, `package-lock.json`, `prisma/`, `tsconfig.json`, `nest-cli.json`, `src/`, `start-production.sh`, `Dockerfile`, and `.dockerignore` under `api/`; no homemade Dockerfile parser is used. Revisit this contract when build context inputs change.

Each mutant driver writes a summary before execution and after each result. Shared `record-run.py` retains pre/post hashes and raw logs; its child invokes the timed step only after hashing. `child-exit.json` records the original argv, child exit and child duration, and `execution.json` reports interruption separately from the recorder exit. A timed-out child and its descendants are reaped before the recorder completes with exit 124. Pending work never becomes success. The server step budget is 2400 seconds (reviewer's loaded-host upper bound, previously 900); hashing is outside that budget. The completed timeout-probe control has a 2400-second safety ceiling. Its measured end-to-end duration sets the timeout probe to `max(10, 4 * baseline)` seconds, and the sleeping child lasts four such budgets; this includes substantial startup margin and does not assume a two-second host. The completed/partial streams and incremental summary assertions remain required.

Parsed YAML governs gate properties. `needs` is normalized to a set (scalar and singleton-list mean the same thing); the new gate genuinely needs two distinct producers, so its flow-list and block-list forms are equivalent. The explicit failure-safe condition contract accepts `!cancelled()`, `always()`, `success() || failure()` and the reversed OR, with or without `${{ }}`, surrounding quotes and whitespace. Unknown expressions fail closed in the test; this is an explicit workflow contract, not a homemade GitHub expression evaluator. `continue-on-error` must be absent or false (including the constant `${{ false }}`). The final shell command is still executed against valid and invalid real records. Removing it or changing it to a successful no-op fails.

`M-D-R4-DR3-05c` was a redundant child-tree declaration: it is now `E-D-R4-DR3-05c`. `M-D-R4-DR3-05missing` removes both the parent inclusion and migration declaration and must fail. The reviewer’s AE5D-01..04 equivalents and the final-gate shell-function equivalent must pass. Mutation anchors identify injected defects; they are not assertions on product source spelling.

Local runs and their timing manifests are kept in `tmp/emr-d/runs/r5d3-*`. Dependency setup, production Docker build and live-suite duration require authorized hosted/integration execution; pure fixture timings do not establish those durations. The increased job bounds give separate budgets to the expanded server mutation matrix and to image/live work, without reducing selections.

The complete refusal-to-test map and gate-removal matrix are in [the part (d) section of the test guide](../../README.md#emr-d-part-d-round-5d3). Every counterexample has a positive control; mutation summaries retain the exact failed case and assertion.
