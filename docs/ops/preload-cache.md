# 판독 PC 암호화 보관 캐시 (D1890)

기준일: 2026-10-30. 이 문서는 승인된 보관 캐시 계약의 구현·운영 절차다. 캐시는 로그인이 허용되는 곳에서 동작하며 기관별 네트워크 제한을 추가하지 않는다. 서버와 판독 PC는 국내 운영을 전제로 한다. 오프라인 열람은 지원하지 않는다.

## 병원 위탁 문구

"판독용 PC는 서버가 사용자별로 발급한 키로 암호화한 영상 사본을 받은 때부터 72시간 동안만 보유하고, 표시 전에 서버의 권한 확인과 열람 기록을 거치며, 보유기간이 지나면 프로그램이 자동으로 지우고 권한이 끝나면 더 읽을 수 없다(개인정보 보호법 제21조·제26조·제29조, 개인정보의 안전성 확보조치 기준 제5조·제7조·제8조·제13조, 의료법 제23조제4항)."

병원은 위 문장을 위탁 문서에 채택한다. 캐시 때문에 처리 목적·원본 보존기간·수탁자가 달라지지 않는다. 내부 관리계획에는 필요하면 같은 문장을 인용한다.

## 저장 항목과 표시 경계

PACS origin의 IndexedDB `kin-preload`에 WADO-RS 프레임 본문과 암호화한 검사 manifest를 보관한다. 프레임은 수신한 gzip 또는 multipart 본문 그대로이며 DICOM 태그 JSON은 저장하지 않는다. manifest는 워크리스트 행 문자열(환자번호(id) · 성명(name) · 검사일(date) · 검사 종류(modality), 200자 이내), UID, revision, 사본 번호, 상태·사유·대기열 순번, 대기·수신 시각, 용량, 프레임 경로 지도를 포함한다. 환자번호를 주민번호로 사용하는 기관에서는 라벨에도 그 번호가 포함되므로 도입 때 데이터 체계와 병원의 처리 근거를 확인한다. 평문 필드는 무작위 레코드 ID·키 ID·만료 시각·암호문 크기·IV뿐이다. Cache Storage와 OPFS는 사용하지 않으며 영상 HTTP 응답은 `no-store`다.

매 열람은 서버의 `check` 읽기로 기관·StudyAccess·분할 UID·보류와 revision을 확인하고 user-view 뿌리 기록을 남긴 뒤 보관 사본을 표시한다. 미리 받기 자체는 background-fetch 전달 기록이며 HEAD는 열람을 만들지 않는다. 기록 실패·네트워크 단절 때 캐시를 대신 표시하지 않는다.

| 사건 | 적용 경계 |
|---|---|
| 검사 접근 종료·분할·보류 또는 revision 변경 | 다음 열람의 check에서 사본 삭제. 진행 중인 열람은 끝까지 유지 |
| 계정 비활성화 | 토큰 갱신 실패(기존 토큰 수명 최대 1800초)로 세션 종료 후 메모리 키 폐기 |
| 로그아웃·세션 종료(기존 유휴 12시간) | 메모리 키·복호화 목록 폐기, 다운로드 중단. 암호문은 보유기간 안에서 유지 |
| 만료 | 표시 전 차단. 실행 중 10분 이내 삭제, 재시작 뒤 첫 응답 전에 삭제 |

## 키 절차

생성: 서버의 CSPRNG로 기관·사용자마다 32바이트 키를 만든다. 활성 키는 한 개이며 동시 발급도 DB의 부분 고유 인덱스로 합쳐진다.

배포: `GET /api/preload/cache-key`는 기존 로그인 세션과 `X-KIN-Session` 결속을 확인한다. 소속 기관이 있고 업무 목록을 읽는 member의 radiologist·technician·admin 역할만 발급받는다. clinician-only에는 발급하지 않는다. 응답은 `no-store`이며 매 발급의 `lastIssuedAt`을 기록한다. 의사의 새 클릭이나 prompt는 없다.

보관: 키는 서버 DB의 `PreloadCacheKey`에 보관한다. 암호문이 있는 판독 PC와 물리적으로 분리하며 소스 코드에 넣지 않는다. 브라우저 SharedWorker는 non-extractable CryptoKey로 가져오고 원시 바이트를 비운다. 창으로 키를 보내거나 디스크 저장소에 기록하지 않는다. 별도 래핑·HSM·정기 교체는 도입하지 않는다.

이용: AES-256-GCM, 매 암호화에 무작위 12바이트 IV를 사용한다. AAD는 manifest의 키 ID·무작위 ID 또는 프레임의 키 ID·UID·경로·revision·copy를 결속한다. 다른 사용자·손상·뒤바뀐 사본은 읽히지 않는다.

파기: 서버가 한 시간마다 72시간 미발급 활성 키의 바이트를 NULL로 만들고 ID·`retiredAt`을 남긴다. 다음 발급에서도 기한을 확인하고 새 키를 만든다. 계정 종료로 더 발급하지 않는 키도 이 규칙으로 폐기한다. 기관 변경은 새 기관의 키를 사용하며 옛 키는 미발급 폐기 규칙을 따른다. 장시간 유지된 세션의 말미에 받은 사본은 키 폐기로 자신의 창보다 일찍 사용할 수 없게 될 수 있으며 그때는 라이브 읽기를 사용한다.

고시 제7조⑥의 대상은 대기업·중견기업·공공기관과 100만명 이상 처리 중소기업·단체다. 적용 여부는 도입 때 확인하는 기관 사실(D585)이며, 위 절차는 규모와 무관하게 제공하고 시행한다.

## 파기 방법·시점·책임과 확인

파기 경로는 고시 제13조②1호의 일부 개인정보 파기다. 응용프로그램의 IndexedDB 삭제 기능을 사용하고, 복구·재생 방지 관리로 암호문만 저장, PC 키 비보관, 인증 세션에만 키 발급, 72시간 미발급 키 폐기, 만료 사본 표시 차단을 함께 적용한다. 브라우저가 제공하지 않는 섹터 덮어쓰기를 했다고 주장하지 않는다.

받은 사본은 첫 저장 프레임의 서버 Date(없으면 키 응답으로 보정한 서버 시각)부터 72시간이다. 열어도 연장하지 않는다. 아직 받지 않은 대기열은 넣은 때부터 72시간이다. 가동 중에는 만료 후 10분 이내, 꺼져 있던 PC는 다음 실행에서 첫 응답 전에 지운다. 만료 시각 이후에는 사본을 표시하지 않는다. Retry로 다시 받은 사본에는 새 시각·copy가 붙는다. Clear All·접근 거절·검사 변경·손상도 레코드를 삭제한다.

운영 수탁자가 이 절차의 실행을 책임지고 병원의 개인정보 보호책임자는 PC의 Preload 패널과 서버 원장의 preload 전달 행으로 상태와 용도를 확인한다. 키 폐기 기록은 DB의 ID·폐기 시각으로 확인한다. 인수 시험 R16은 양쪽 object store에서 레코드가 없어지고 모델이 참조하지 않으며 다음 열람이 라이브 읽기인지 확인한다. 저장 사용량 감소는 무삭제 대조 실행과 함께 측정하여 브라우저 bookkeeping의 허용 폭을 정한다(M-D5). 이 문서의 존재만으로 해당 인수 시험을 완료했다고 세지 않는다. 프레임별 파기 수신 원장은 새로 만들지 않는다.

## 기관 사실과 근거 표기

고시 제6조의2의 일일평균 100만 이용자 기준은 병원 네트워크 조치의 적용 사실이며 캐시로 새 접속 경로가 생기지 않는다. 제11조의 재해 대비 적용 규모와 복구 계획은 아카이브 운영에서 확인한다. 캐시는 재구성 가능한 사본이며 원본 백업이 아니다. 개인정보 보호법 제33조의 영향평가는 공공기관 해당 여부에 따른다. 원장의 법정 항목·보존·위변조 방지, 기존 계정 권한 변경 기록, 외부 로그인 인증수단 및 PC 보안 관리는 도입 때 기존 운영에서 확인한다. 인증을 보유·추진하는 경우 기능 변경 신고 대상인지 확인한다.

2026-10-30 열람 기록의 현행 근거는 개인정보 보호법 제29조·시행령 제30조①5호·고시 제8조다. 고시 제8조② 신 문언은 부칙 제2025-9호에 따라 2026-11-01 시행이고, 그 전에는 월 1회 점검·다운로드 사유 확인의 구 문언을 적용한다. 의료법 제23조④의 열람 문언(법률 제21776호, 2026-12-10 시행)은 선제 준수(D576)다. 미래 하위규정 공포 때 다시 대조한다. 암호화는 유출 통지·신고의 자동 면제를 뜻하지 않는다.

## 운영 설정과 측정

`KIN_PRELOAD_DISK_GB` 하나를 기관 운영 설정으로 두고 `/api/me`의 `preloadDiskGb`로 전달한다. 단위는 1024³바이트이며 양수만 허용한다. 기본값은 없다. 미설정·저장소 사용 불가 때 패널에 사유를 표시하고 영상 열람은 라이브로 진행한다. 브라우저 quota도 지킨다. 만료분, 다른 키의 사본(만료가 빠른 순), 열었다 닫은 검사(오래 닫힌 순)부터 비운다. 열린 검사와 아직 읽지 않은 Ready 검사는 공간 때문에 지우지 않으며 공간이 없으면 Queued로 기다린다.

첫 기관 값은 판독 PC의 `navigator.storage.estimate()`와 판독 중 여유 공간을 측정해 정한다(M-D3). M-D1은 SharedWorker의 2MB × 300 레코드 읽기·쓰기·복호화·gunzip, M-D2는 AES-GCM 시간, M-D4는 실제 브라우저 종료·PC 재부팅 복원, M-D5는 삭제 사용량 감소를 확인한다. 장비와 브라우저 버전·원문 결과를 인수 기록에 남긴다. 미측정을 추정치로 통과 처리하지 않는다.
