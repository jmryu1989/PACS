# EMR 단위 A — 분류와 계약

이 디렉터리는 합의된 요구를 후속 구현에 전달하는 순수 계약이다. 기존 API·DB·인증·화면에는 연결하지 않는다. 기관 입력 없이 모든 관련 법령을 준수하는 제품 계약이며 기관 설정은 보호를 강화하는 방향만 허용한다. A의 순수 함수 검증은 후속 저장소·키 보관·API 연결의 실제 이행 완료나 모든 법령 준수 인증을 뜻하지 않는다.

|---|---|---|
| `classification.ts`, `routes.ts` | 저장 모델·API 응답·DB 밖 영상/출력의 기록 종류와 책임·보존 분류. 혼합 자료는 여러 종류로 분류 | B, E, F, L, M, N, Q |

## 제품 기본값과 근거

법 적용은 기관이나 계약 시점의 선택 사항이 아니다. `DEFAULT_CONFIGURATION`은 모든 기록 종류의 보존·접속기록 기간·서명 설정을 완전히 채운 불변 객체다. `tightenConfiguration()`은 빈 입력도 즉시 사용 가능하게 해석하고, 알 수 없는 종류·필드, 명시적 `undefined`/`null`, 음수·비정수·비유한 연수, 기존 보호보다 약한 설정을 거절한다. 런타임에 결정 대기값은 없다. 실제 작성자·관리기관은 인증/저장 문맥에서 얻으며 가상의 기관 ID나 서명자를 만들어 채우지 않는다.

임상 종류는 전자의무기록 후보이고 모든 이전 판을 보존한다(의료법 제22조②). 개인 초안도 모든 저장판을 보존하되 저자 이외에게 공개하거나 자동 서명하지 않는다. 배정·순수 배치·설정은 운영 기록이다. 운영 칸에 임상 내용이 들어가면 저장 전에 임상 분류를 함께 적용한다. 취소·비우기·버리기는 상태 사건이며 과거 판의 물리 삭제가 아니다. 제23조④ 개정 문언에 맞춰 기재·추가기재·수정·열람 접속기록을 항상 남긴다. 개정 시행 전에도 이 보호를 적용한다.

|---|---|
| 판독 현재판·불변판(수정·Addendum 포함), 영상, 수동 SR, 외부 SR/SEG, 측정·Key Image, 취득 메타데이터·썸네일 | 영상/검사 소견 자료 5년: 시행규칙 제15조①5·6. 진료기록부에 결속되면 그 10년을 함께 적용 |

| 접속기록·전달 증거 | 2년과 연결 기록 자체의 기간 중 긴 기간. 민감정보 처리 시스템 접속기록 2년은 안전성 확보조치 기준 제8조①2에서 확인. 원기록 기간까지 함께 보존하는 것은 제품의 강화 기본값 |
| 배정·순수 배치·환자 없는 양식·환경 설정·계정/세션·기관·시스템 운영 | 확인한 조문에 독립적인 의무기록 보존 최저 연수 없음(계약상 0). 목적 종료 후 명시적 파기 대상; 연결 임상 기록과 보안/접속 증거에는 각각의 더 긴 기간 적용. 인증 비밀은 임상 보존물로 복제하지 않음 |

`retentionFor()`에 실제 기록과 연결 자료의 모든 종류를 전달하면 가장 긴 기간을 적용한다. `accessYears`는 각 기록의 `retentionYears`와 2년 이상이어야 하며, 기록 기간을 늘리면 접속기록도 자동으로 늘어난다. 기산은 가장 최근 저장판 또는 임상 사용 시각부터이며, 더 늦은 연결 기록 만료·접속기록 만료를 함께 지킨다. 이는 조문에 없는 기산점을 법정 해석으로 단정한 것이 아니라 조기 파기를 막는 제품 규칙이다. 모든 이전 판과 원서명 검증 자료가 같은 경계를 따른다.

자동 파기는 허용하지 않는다. `destroyAfterDurableEvent()`는 기간 경과, 보존 hold 해제, 명시적 행위자·사유·법적 근거 참조, 전체 판 ID와 연결 만료 목록을 요구하고 파기 사건의 내구성 확인 후에만 실행 콜백을 호출한다. 기간이 지났다는 사실만으로 파기가 자동 허용되지 않는다. B/G는 실제 권한, 근거, 모든 판/연결 자료의 완전성, 동시 수정 방지, 파기 결과/실패 감사와 복구 불가능한 삭제를 저장소에서 보장해야 한다. A의 메모리 영수증 시험으로 이를 입증하지 않는다.

## 서명 경계

제22조①·제23조①은 의료인이 진료에 관한 사항·의견을 전자의무기록으로 작성하는 경우의 서명 근거다. 모든 DB 행에 개별 전자서명이 필요하다는 조문은 아니다. 각 종류의 근거와 설명은 `classification.ts`에 빠짐없이 있다.

| 종류 | 기본 서명 동작 |
|---|---|
| 판독과 모든 수정/Addendum, 임상 Q&A, 협진, Critical Result 내용, Finding, 수동 임상 SR, 임상 비교 설명, 임상 Order | 진료 기재이므로 각 작성판에 전자서명 필요(제22조①·제23조①) |
| 개인 초안·dictation, Tech Note, 단순 ACK, 영상 전달 요청, 정정/환자 연결 사건, 분류표의 자유 문구 | 그 작업 행위 자체의 별도 서명 의무는 확인한 조문에 명시되지 않음. 작성자+서버 시각+해시를 남김. 의료인의 진료 기재/임상 사용 또는 서명된 기록의 정정이면 `signatureRequired(kind, 'clinical-entry')`가 반드시 서명을 요구 |
| 측정·Key Image·영상·썸네일·메타데이터, 외부 SR/SEG, 판독 인용/첨부·임상 문맥, 출력·PDF·복사·다운로드·제공 | 원자료와 작성자+시각+해시·원서명/출처 증거 보존. 자료 선택/형식 변환 자체에 새 서명 의무를 발명하지 않음. 이 자료로 새 진료 의견을 기록하면 해당 문서는 서명 필요. 외부 AI 원문은 재해석/재서명하지 않음 |
| 접속·전달·서명 검증·전송 근거 증거, 배정·배치·설정·양식·계정/세션·기관·시스템 운영 | 제23조①의 독립 진료 기재 서명 의무 없음. 작성자+시각+해시 및 기존 업무별 증거 계약 적용 |

`clinical-entry` 여부는 기관의 설정이 아니라 실제 기재 내용과 사용 흐름에서 서버가 정한다. 입력을 단순 작업 자료라고 표시하여 서명된 진료 기재를 우회할 수 없다. 기관은 서명을 추가로 요구할 수 있으나 필수 서명을 해제할 수 없다. 서명 의무가 없는 자료도 임상 후보에서 제외하거나 이전 판을 지우지 않는다.

## 제품이 운영하는 키

`KEY_MANAGEMENT`는 의사별 개인 키, 보호 키 볼륨, DB/키 볼륨 밖 별도 secret, 암호화 보관, 제품의 의료인 신원·서명 권한 확인을 고정한다. 개인 키를 브라우저나 감사로그로 내보내지 않는다. 복구는 신원·권한 재확인, 서로 다른 두 운영자의 승인, 암호화 백업과 분리된 secret을 요구하며 새 `kid`를 발급한다. 이전 키는 복구 후 재활성화하지 않는다. 분실·침해·퇴사 시 즉시 신규 서명을 차단하고 사유·효력 시각을 남긴다. 공개키·등록/폐기 이력은 과거 서명 검증을 위해 원기록과 함께 보존한다. 실패 시 서명을 막되 초안과 기존 서명은 보존한다.

의료법 제23조①②·시행규칙 제16조①1·2·3·5·6은 서명 검증·이력·백업·보안·접근 방지의 근거다. 의사별 키 볼륨/분리 secret과 복구 방식은 그 보호를 수행하는 제품 기본 설계이며 법 조문이 특정 구현을 지정했다는 뜻은 아니다. 실제 키 저장소와 복구/폐기 실행은 C의 구현 대상이고 A에서는 계약과 키 상태 전이만 제공한다.

지휘자가 확인할 쟁점은 다음과 같다. 이 항목은 기관 입력이나 결정 대기가 아니며 기본 보호 설정을 비우지 않는다.

- **장기 보존의 상한과 목적:** 시행규칙 제15조① 단서는 계속 진료를 위한 1회 연장을 규정한다. 개인정보 보호법 제21조①·③은 불필요한 정보의 지체 없는 파기와 법정 보존 자료의 분리 관리를 규정한다. 단순히 연수를 늘리는 설정만으로 무제한 보유의 적법성을 만들 수 없다. 임상 후보·사본·접속 증거를 원기록 기간까지 연계 보존하는 범위, 추가 연장의 정당한 근거, 목적 종료/분리 관리/지체 없는 명시적 파기 절차를 지휘자가 법적으로 확정해야 한다. 설정 검증은 보호 하한 검사이며 모든 연장의 적법성 판정이 아니다.
- **판본 검증의 한계:** 고시의 부칙 및 시설·장비 기준 제7조의 기관 외 보관 별표는 원문 미확인이다. 본문에서 확인한 제8조①2의 2년 하한, 시설·장비 기준 제3~6조의 서명 검증·이력·백업·보안 보호를 적용하되 미확인 별표나 미래 개정까지 준수 검증을 끝냈다고 표시하지 않는다. 관련 법령 변경은 제품 계약 갱신 대상으로 관리한다.

## 사건과 서명 바이트

`write`/`additional-entry`/`modify`는 기재/추가기재/수정이다. 승인·서명, amendment, Addendum, 취소, 점유 해제, 초안 저장/비우기/버리기는 각각 별도 행위다. `provide-prepared`는 서버 제공 준비이고 전송 종료·중단, 클라이언트 표시, 명시적 ACK와 같지 않다. 후속 사건은 앞 사건과 동일한 대상/판에 결속한다. `user-view`/`background-fetch`/`service-job`은 원인을 구분하며 사람의 인지를 증명하지 않는다. 출력·PDF·Copy의 클라이언트 보고는 실제 프린터·OS 저장 완료 증명이 아니다.

필수 칸은 생략할 수 없다. 인증 실패 등으로 확인할 수 없는 신원/환자는 `unresolved`와 원인을 기록한다. 실제로 해당하지 않는 칸은 사유 있는 `not-applicable`로 구분한다. 성공 제공의 대상은 그때 반환한 집합이며 나중에 검색해 재구성하지 않는다. 빈 목록은 빈 대상 집합을 명시한다. G는 신뢰 프록시에서만 IP를 취하고 B는 append-only 저장과 독립 실패 저널을 구현해야 한다. 감사 연결 ID는 독립 난수 `audit:<UUID>`이며 인증 계층이 세션·토큰으로 받아서는 안 된다. 순수 검증만으로 DB 내구성·프록시 신뢰·인증 거절을 입증하지 않는다.

서명 v1은 `SignaturePayload`의 필드를 `canonicalPayload()`에 적힌 순서로 직렬화한 JSON UTF-8 바이트다. 중첩 객체도 고정 순서이고 배열은 입력 순서, 빈 문자열과 `null`은 명시적으로 유지한다. BOM·끝 줄바꿈·JSON 장식 공백을 넣지 않는다. **본문의 공백·CR/LF·Unicode 조합 형태는 변환하지 않는다.** NFD와 NFC는 다른 원문으로 서명하며 홀로 있는 surrogate, 알 수 없는 필드/형식은 거절한다. 형식을 바꿀 때 버전을 올린다. 이전 판과 첨부는 기록/판 ID와 SHA-256을 함께 고정한다.

JWS는 `{protected,payload,signature}` 형식의 unpadded base64url이며 보호 헤더는 `alg`, `kid`, `typ` 순서, 값은 ES256·등록 키 ID·`emr-signature+jws`이다. 서명값은 64바이트 R||S다. `inspectSignatureEnvelope()`는 구조만 검사한다. C는 기존 암호 도구로 내용 무결성, 제품이 확인·등록한 신원, 서명 당시 키의 소유/활성 상태를 각각 검증하고 침해 의심 기간을 별도 표시해야 한다. 현재 DB 머리에서 payload를 재조립하거나 나중의 키 폐기만으로 이전 서명을 지우지 않는다.

## 판독 상태와 검증 범위

첫 입력→In Progress, Save→개인 중간 저장, 다른 판독의의 Release→Unread와 점유 세대 증가다. Release는 모든 개인 초안을 보존한다. 세대가 오래된 저장·갱신은 거절한다. Approve는 즉시 공개하고 `firstApprovedAt`·`originalSignerId`·`amendUntil`을 함께 고정한다. 24시간 직전까지만 원서명자의 새 서명판 amendment를 허용하며 정확히 기한에 도달하면 거절한다. 다른 작성자의 Addendum은 별도 불변 참조로 유지된다.

Finalized는 공개판을 유지한다. 처리 지연이 있어도 효력 시각은 `amendUntil`이며 기한을 늘리지 않는다. 사유 있는 취소는 Cancelled와 취소 사건으로 남고 기존 공개판 참조·본문·Addendum·시계를 보존한다. 이 참조는 이력용이며 소비자는 Cancelled를 정상 유효 판독으로 표시해서는 안 된다. Reset 명령·재승인·Unread 복귀는 허용하지 않는다. P의 지정 상급자 승인·자기 승인 금지와 Defer 사유도 계약에 포함한다. 순수 함수의 역할/기관/서명 권한 입력은 G가 검증한 문맥이어야 한다. I는 제출한 이전 판, 새 판 ID의 전체 이력상 유일성, 서명 검증, 상태·공개·감사의 원자성을 DB에서 확인한다. 개인 초안 revision과 점유 세대, 확정판 경쟁 조건은 별개다.

REQ-EMR-01/17/19 → RISK-EMR-01/17/19 → TEST-EMR-01/17/19-A는 분류 누락·보존 하한·강화 전용 설정·미정값 부재·파기/키 경계를 검사한다. REQ-EMR-04/05 → RISK-EMR-04/05 → TEST-EMR-04/05-A는 바이트 결속·봉투를 검사한다. REQ-EMR-06/07 → RISK-EMR-06/07 → TEST-EMR-06/07-A는 사건 필드·내구성 선후를 검사한다. REQ-EMR-02/12/13 → RISK-EMR-02/12/13 → TEST-EMR-02/12/13-A는 점유·역할·기한·취소를 검사한다. REQ-EMR-20의 실제 최종 CI·G3·독립 판정·법령 재대조·제품 운영 증거는 R에 남는다.

시험 `tests/emr_contract_test.cjs`는 설치된 Prisma의 generator 프로토콜로 현재 schema의 DMMF를 받고 TypeScript AST로 전체 API 라우트를 수집한다. 새 모델·라우트를 기존 분류에 자동 편입하지 않는다. 프록시·브라우저 제공면은 별도 명시 목록이며 N/O에서 실제 제공·인가·실패 시험으로 결속한다. 암호 서명, 실제 DB/네트워크, 운영 보존, 의사 확인은 이 순수 시험의 범위 밖이다.

`routes.ts`의 `ROUTE_CONTRACTS`는 각 정확한 경로에 기록 종류, 업무 행위(`read`/`write`/`export`/`auth`), 호출 원인 종류를 명시한다. `ROUTE_CLASSIFICATION`은 기록 종류만 필요한 소비자를 위한 같은 목록의 투영이다. 호출 원인 목록은 가능한 호출 문맥이며 실제 사건의 원인을 선택하는 기본값이 아니다. 후속 구현은 사용자 동작·백그라운드 요청·서비스 작업 중 실제 원인을 결속해야 한다. DICOM 인가의 204는 영상 제공 증거가 아니고, 출력 미리보기는 출력 완료 증거가 아니다. 경로 판독은 문자열 패턴 대신 TypeScript가 해석한 실제 Nest 데코레이터 export 심볼을 대조한다.
